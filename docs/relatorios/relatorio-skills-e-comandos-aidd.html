Ecossistema AIDD · Auditoria de Skills

Mapa de Skills e Comandos

Quatro camadas de skills convivem no monorepo: os quatro runners canônicos da raiz, os quality gates que os fecham, as skills locais de cada ferramenta em tools/*/.claude/skills, e os templates que o Forge injeta em projetos de terceiros. Este relatório documenta o que cada uma executa, seus comandos, e onde a fiação realmente conecta — incluindo um ponto de integração que está documentado mas não é descoberto pelo Skill tool do Claude Code.

Fonte: AGENTS.md + inspeção direta dos 4 subprojetos 4 camadas · 15 skills mapeadas

Camada 1 · Orquestrador raiz

skills/*-runner

Cada skill é um wrapper 1:1 para um subcomando de ecossistema.py, que roteia para o script real dentro de tools/<ferramenta>.

SkillComandoExecutaIntegração
aidd-forge-runner /forge [caminho] aidd_forge.cli em tools/aidd-forge não descoberta
aidd-generator-runner /generate <ideia> pipeline_completo.py · 8 fases não descoberta
aidd-master-runner /master <modulo> scripts/aidd.py add-module não descoberta
aidd-enterprise-runner /enterprise <tipo> <nome> scripts/aidd.py inject não descoberta

Gap de integração real. As 4 skills vivem em skills/ (espelhadas em .agent/skills/ para Antigravity/MimoCode/OpenCode), mas nunca em .claude/skills/. O Skill tool do Claude Code só descobre skills sob esse caminho — confirmado nesta própria auditoria, onde apenas as skills de tools/*/.claude/skills foram auto-registradas.

Na prática, quem dispara /forge no Claude Code é o prompt-texto em .claude/commands/forge.md, que instrui a rodar python ecossistema.py forge init via Bash — a skill referenciada dentro dele é documentação, não execução. Isso contraria a Regra de Ouro nº6 do AGENTS.md (Supremacia Agnóstica).

Camada 2 · Quality Gates

gates/*.py

Não são skills — são o fecho determinístico que qualquer skill acima deve respeitar antes de commit. Disparados em bloco via python ecossistema.py audit.

GateAudita
G_ECOSSISTEMA_INTEGRIDADEIntegridade física/sintática/estrutural dos 4 subprojetos e skills
G_DRIFT_NUCLEO_COMPARTILHADODivergência não documentada entre núcleo compartilhado master/enterprise
G_HARNESS_COMPATSincronismo dos artefatos multi-harness (comandos, skills, ponteiros)
G_SEGREDOSCredenciais hardcoded em todo o repositório rastreado pelo git
G_CLI_HELP_CONSISTENCIAFlags citadas em print/raise vs. flags definidas via argparse (AST)

Camada 3 · Skills locais por ferramenta

tools/*/.claude/skills

Descobertas nativamente pelo Skill tool ao trabalhar dentro do subdiretório da ferramenta. Duas têm lógica própria implementada; duas são esqueletos gerados pelo Injetor Universal, sem fluxo de execução codificado.

SkillOndeO que executaComandoStatus
resumo-sessao aidd-master, aidd-enterprise Exporta histórico da sessão para secoes/*.md (telemetria, timeline, artefatos) /resumo-sessao lógica própria
project-spec-tracker aidd-generator SPEC vivo com SQLite (fase/item/status/quem/commit), gera MD/HTML/PDF /project-spec-tracker lógica própria
seguranca-cibernetica aidd-master Esqueleto de auditoria OWASP/hardening — sem lógica própria linguagem natural gerado, genérico
auditoria-seguranca-dependencias aidd-generator Audita requirements.txt contra padrões de risco — sem lógica própria /auditoria-seguranca-dependencias gerado, genérico
validador-contratos aidd-forge/sandbox-forge-teste Um-liner: valida payloads JSON contra schema — fixture de teste — fixture

Duplicação por harness: resumo-sessao repete idêntica em .claude/.agent/.mimocode; seguranca-cibernetica repete em .claude/.gemini/.mimocode/.agent — mesmo conteúdo, uma cópia por convenção de harness.

Camada 4 · Templates do Forge

aidd_forge/templates/skills

Não servem ao próprio ecossistema — são copiadas para o projeto-alvo quando alguém roda /forge nesse projeto. Cada uma carrega um gate de saída explícito (exit 0 só sob condição verificável), padrão mais rigoroso que a Camada 3.

SkillPapel no pipeline injetado
caveman-ultraRaciocínio interno telegráfico + saída PT-BR para todo subagente efêmero
orca-orchestrationMulti-agente em worktrees isoladas por worker + decision gates p/ schema e segredo
impeccable-uiDesign system Slate/Indigo, modais WCAG 2.1, zero emoji em UI de produção
open-code-reviewLinter de acoplamento Clean Architecture via grafo de imports real
post-mortem5-Porques após falha de gate, antes de qualquer patch aplicado
cybersecurity-auditVarredura estática OWASP Top 10 em modo cego, somente relatório

Como a fiação conecta

01Slash command/forge, /generate, /master, /enterprise
02.claude/commands/*.mdprompt-texto lido pelo Claude Code
03ecossistema.pyroteia p/ script real da ferramenta
04tools/<ferramenta>skills locais cobrem sessão/spec/segurança
05ecossistema.py audit5 gates antes do commit

Correção recomendada. Espelhar skills/*-runner também para .claude/skills/*-runner, para que o Skill tool nativo do Claude Code as descubra sem depender só do slash-command manual.
