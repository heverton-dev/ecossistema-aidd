# Glossário — termo → frase do dia a dia

> Usado pelo Quarteto (`/docs`) e pelo perfil leigo. Sigla sempre traduzida na 1ª ocorrência.

| Termo | Frase do dia a dia |
|---|---|
| Harness | Programa de conversa / assistente (Claude, Gemini, Cursor…) |
| Quality gate / portão de qualidade | Travas automáticas que aprovam ou barram uma mudança |
| Drift | Quando duas cópias do mesmo arquivo deixam de bater |
| Handoff | Passagem de bastão: o que a etapa seguinte precisa saber |
| Worktree | Cópia de trabalho isolada do projeto, sem bagunçar a original |
| VSA — Arquitetura por Fatias Verticais | Cada pedaço do app fechado em si (dados + regra + tela) |
| Fatia vertical | Esse pedaço fechado em si |
| Pipeline | Fila de etapas em ordem, uma depois da outra |
| Orquestrador | Quem comanda a fila de etapas |
| Preflight | Checagem rápida do computador antes de decolar |
| E2E — ponta a ponta | Teste do começo ao fim, como o usuário faria |
| BDD | Escrever o que o sistema faz em cenários do dia a dia |
| SDD | Descrever o sistema antes de codar |
| Quarteto Sine Qua Non | Os 4 estúdios obrigatórios: `/api`, `/webhook`, `/mcp`, `/docs` |
| Rule 10 (Formato de Resposta) | Como a resposta deve ser escrita (curta, sem enrolação) |
| Lei #10 (Quarteto) | A regra dos 4 estúdios — não confundir com Rule 10 |
| Lei #4 (Idioma) | PT-BR simples para você; inglês curto para o motor |
| SHA-256 | Impressão digital digital: muda 1 bit, muda o número |
| Lock-in | Prender o app a um fornecedor só |
| Backend | O motor do app (o que calcula e guarda dados) |
| Frontend | A tela que você vê e clica |
