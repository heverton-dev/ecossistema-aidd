As 7 Engrenagens do
Ecossistema AIDD

Compreenda o papel, o objetivo primordial e as entregas concretas de cada uma das sete ferramentas, eliminando sobreposições e garantindo o padrão Vertical Slice Architecture (VSA) de ponta a ponta.

Zero Mocks / Zero Stubs Quality Gates Binários (0 ou 1) Quarteto Sine Qua Non

1. Visão Geral e Princípio de Independência

Cada ferramenta é um elo autônomo e complementar de uma esteira industrial de software.

🎯

Fronteira Delimitada

Nenhuma ferramenta tenta resolver tudo. Cada uma possui uma entrada (Input) clara, uma transformação determinística e uma saída (Output) auditável.

⚡

VSA Universal

Todo código gerado no ecossistema é organizado em Fatias Verticais (Vertical Slice Architecture), garantindo que cada funcionalidade carregue suas próprias rotas, regras, repositórios e testes.

🛡️

Quality Gates

Cada ferramenta possui seu conjunto de Quality Gates automatizados (`G_*`). Se o gate falhar (Exit 1), a esteira é bloqueada até que a conformidade seja restaurada.

2. O Quarteto Sine Qua Non Dinâmico

Os 4 estúdios que toda aplicação do ecossistema DEVE expor nativamente.

PILAR 1

Swagger Studio (`/swagger`)

Contratos de API REST OpenAPI 3.0 dinâmicos, totalmente tipados e interativos para teste direto no navegador.

Contratos REST Vivos
PILAR 2

Webhook Studio (`/webhooks`)

Gerenciamento, testes, simulações e validação de assinaturas HMAC SHA-256 para comunicação assíncrona entre sistemas.

Assinaturas HMAC & Logs
PILAR 3

MCP Studio (`/mcp`)

Exposição padronizada de ferramentas (tools) e recursos via Model Context Protocol para orquestração direta por agentes de IA.

Model Context Protocol
PILAR 4

Guia do Usuário (`/docs`)

Documentação viva de produto com instruções claras de uso de cada rota, credenciais e integrações para operadores humanos.

Manuais Vivos

3. As 7 Ferramentas: Papel, O que Faz e O que Entrega

O mapa exato de competências e saídas tangíveis de cada componente do ecossistema.

🛠️
Ferramenta 01

aidd-forge

O Fundador & Blindador de Governança

Fase Zero • Infraestrutura de Código

🎯 Objetivo da Ferramenta

Estabelecer a fundação canônica, governança inquebrável e regras arquiteturais de um projeto antes de qualquer código de negócio ser produzido.

⚙️ O que ela Realmente Faz

  • Inspeciona o ambiente local e instala git pre-commit hooks.
  • Injeta arquivos de governança canônicos (AGENTS.md, CLAUDE.md, GEMINI.md).
  • Configura linters e determinismo para blindagem do repositório.

📦 O que ela Realmente Entrega

  • Repositório com governança ativa e inquebrável.
  • Gates de auditoria inicial aprovados (G_FORGE_*).
  • Ambiente isolado pronto para desenvolvedores humanos e agentes de IA.
🏭
Ferramenta 02

aidd-generator

A Fábrica Autônoma de Software End-to-End

8 Fases • Da Ideia ao Deploy

🎯 Objetivo da Ferramenta

Construir sistemas completos do zero sem alucinações, guiado por uma esteira determinística de 8 fases (Intake -> TDD -> VSA -> Quarteto -> Auditoria).

⚙️ O que ela Realmente Faz

  • Escreve primeiro testes de integração reais (TDD Red-Green).
  • Implementa fatias verticais VSA completas (Zero Stubs).
  • Gera automaticamente os 4 estúdios do Quarteto Sine Qua Non.
  • Valida o software contra 100% dos Quality Gates da factory.

📦 O que ela Realmente Entrega

  • Aplicação completa e funcional com servidor FastAPI/Node.
  • Suíte de testes reais rodando e passando 100%.
  • Swagger, Webhooks, MCP e Docs vivos e integrados.
📐
Ferramenta 03

aidd-master

O Arquiteto Modular de Fatias Verticais (VSA)

Modelagem de Domínio • Fatias Isoladas

🎯 Objetivo da Ferramenta

Esculpir a lógica de negócio do domínio através de fatias verticais isoladas, evitando código espaguete e acoplamentos cruzados em sistemas complexos.

⚙️ O que ela Realmente Faz

  • Separa o negócio em fatias autônomas (features/).
  • Estrutura cada fatia com rotas, regras, repositórios e esquemas próprios.
  • Conecta as fatias ao roteador central de forma declarativa e limpa.

📦 O que ela Realmente Entrega

  • Módulos de negócio independentes prontos para evolução paralela.
  • Roteamento unificado sem dependências circulares.
  • Isolamento de banco e entidades por fatia vertical.
🛡️
Ferramenta 04

aidd-enterprise

O Guardião de Missão Crítica & Resiliência Bancária

SHA-256 • Resiliência & Auditoria

🎯 Objetivo da Ferramenta

Garantir que a aplicação suporte cargas pesadas e requisitos bancários, injetando segurança criptográfica, resiliência e trilha de auditoria imutável.

⚙️ O que ela Realmente Faz

  • Valida a integridade do código via hash SHA-256 anti-tampering.
  • Injeta Circuit Breakers, Rate Limiting distribuído e Retries.
  • Aplica sanitização estrita de dados contra SQL Injection e XSS.
  • Cria trilha de auditoria (audit trail) com correlação de logs (trace_id).

📦 O que ela Realmente Entrega

  • Componentes de segurança enterprise injetados na aplicação.
  • Relatório formal de conformidade criptográfica e resiliência.
  • Código tolerante a falhas preparado para escala corporativa.
☁️
Ferramenta 05

aidd-ops

O Orquestrador de Infraestrutura, VPS & Observabilidade

Infraestrutura como Código • Deploy SSH

🎯 Objetivo da Ferramenta

Provisionar e colocar o sistema em produção com segurança máxima, orquestrando servidores VPS, containers Docker, criptografia de segredos e monitoramento.

⚙️ O que ela Realmente Faz

  • Gera o PLANO-INFRAESTRUTURA.json e manifestos docker-compose.yml.
  • Executa provisionamento remoto determinístico via SSH seguro (G_OPS_SSH).
  • Protege segredos com chaves sops + age.
  • Configura observabilidade ativa com Uptime Kuma e métricas.

📦 O que ela Realmente Entrega

  • Servidores e containers operando em produção com SSL/Reverse Proxy.
  • Cofre seguro de variáveis de ambiente.
  • Painel de monitoramento ativo alertando sobre quedas em tempo real.
⚙️
Ferramenta 06

aidd-factory

O Integrador de Motores Open-Source & Fatias Periféricas

Integração de Motores • VSA Periférico

🎯 Objetivo da Ferramenta

Acelerar o desenvolvimento integrando motores open-source existentes (ex: mensageria, filas, bots, gateways) e gerando o código de conexão VSA tipado e seguro.

⚙️ O que ela Realmente Faz

  • Recebe a necessidade ou o plano de infraestrutura de serviços.
  • Gera o código de aplicação (fatias verticais VSA) para consumir cada motor.
  • Cria clientes tipados, endpoints de webhooks e tratamento de erros.
  • Expõe os 4 estúdios do Quarteto Sine Qua Non para toda a periferia.

📦 O que ela Realmente Entrega

  • Fatias de integração VSA nativas com Swagger, Webhooks e MCP.
  • Clientes de integração tipados com proteção contra falhas.
  • Manifesto Compose dos serviços periféricos para orquestração.
🌉
Ferramenta 07

aidd-bridge

O Empacotador de Protótipos Low-Code para Produção

Zero Lock-in • Lovable/v0/Bolt para VPS

🎯 Objetivo da Ferramenta

Resgatar telas e protótipos construídos em plataformas low-code ou ferramentas visuais de IA, libertando-os de amarras proprietárias para rodarem em VPS corporativa.

⚙️ O que ela Realmente Faz

  • Analisa o código exportado do Lovable, v0 da Vercel ou Bolt.new.
  • Remove dependências proprietárias de cloud fechada e backends mockados.
  • Reconecta o frontend ao banco de dados PostgreSQL corporativo.
  • Gera o container Dockerfile de produção com Nginx/Traefik otimizado.

📦 O que ela Realmente Entrega

  • Frontend limpo, desatado e padronizado em React/Next.js/Vite.
  • Conexão direta aos endpoints de backend VSA gerados no ecossistema.
  • Container e scripts prontos para deploy direto na VPS via aidd-ops.

4. Matriz Comparativa Resumida

Entrada, processamento e momento ideal de acionamento.

Ferramenta Entrada Principal Entrega Central Quando Usar?
🛠️ aidd-forge Pasta vazia / Novo repositório Repositório blindado com AGENTS.md No Dia Zero de qualquer projeto
🏭 aidd-generator Requisitos ou Ideia de Negócio Aplicação funcional + 4 Estúdios Para criar sistemas completos do zero
📐 aidd-master Modelos de negócio / Domínio Fatias VSA de Domínio desacopladas Para desenhar o núcleo de regras de negócio
🛡️ aidd-enterprise Aplicação existente / Código VSA Componentes de resiliência e auditoria Para elevar o sistema a padrão de banco
☁️ aidd-ops Requisitos de infra / Plano VPS com Docker, sops+age e Kuma Para provisionar servidores e colocar no ar
⚙️ aidd-factory Necessidade de motores externos Fatias VSA de integração + Compose Para integrar serviços open-source periféricos
🌉 aidd-bridge Export Lovable / v0 / Bolt Frontend limpo em container para VPS Para resgatar protótipos de low-code

5. Como as Ferramentas Cooperam na Prática

O pipeline unificado desde o nascimento até a produção.

1
aidd-forge
Prepara o solo, cria as regras e blinda o repositório.
──────▶
2
aidd-master / bridge
Esculpe o domínio em VSA e desata telas low-code.
──────▶
3
aidd-factory
Conecta motores open-source periféricos em fatias VSA.
──────▶
4
enterprise + ops
Injeta resiliência SHA-256 e coloca na VPS.
💡 Conclusão Arquitetural: Com essa separação nítida de responsabilidades, o ecossistema elimina o risco de uma ferramenta desrespeitar ou sobrescrever a arquitetura da outra. O resultado é sempre um sistema modular, resiliente, auditável e 100% sob o controle do desenvolvedor.
