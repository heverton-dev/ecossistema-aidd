Mapa das skills

Uma skill é um manual de tarefa: uma pasta com um SKILL.md que ensina o agente a fazer uma coisa do jeito da casa. Este mapa mostra todas as skills que existem hoje e resume como construir uma nova sem repetir as que já existem.

O quê · por quê · para quê

Por que o ecossistema precisa de skills

O que é

Um manual que o agente só abre quando a tarefa combina com a descrição. Até lá, ele lê apenas o nome e a descrição de cada skill. Por isso a descrição é o gatilho.

Por que construir

Para a mesma tarefa sair do mesmo jeito em toda sessão, sem alguém explicar de novo: a ordem certa, os comandos exatos, as armadilhas já vividas.

O que não é

Skill ensina; guarda confere. Se a regra precisa ser obrigatória, ela precisa de um guarda (veja o mapa dos guardas).

Quando

Quando criar, e quando não

Crie quando…

  • você explicou a mesma coisa ao agente pela segunda vez;
  • a tarefa tem uma ordem de passos que não pode variar;
  • existe um script pronto que o agente deve rodar em vez de reescrever;
  • uma ferramenta nova precisa de um "como usar".

Não crie quando…

  • já existe uma skill com o mesmo trabalho (procure na lista abaixo);
  • é só um atalho com outro nome: atalho é comando slash, não skill;
  • é algo que o modelo já sabe sozinho;
  • a skill é de outro fornecedor: ela entra pelo instalador dele, não por cópia.
Onde

Onde cada coisa mora

Fonte única

componentes/compartilhado/skills/<nome>/

O único lugar onde se edita. As pastas dos harnesses (.claude/, .agents/, .opencode/…) são cópias geradas pelo components sync.

Atalho para pessoas

componentes/compartilhado/comandos/<nome>.md

O que você digita (/pure, /melhoria, /plan) pode ter nome em português e só chama a skill aidd-*.

Skill de terceiros

gates/dependencias_externas.json

Registrada com dependencia add-skill e instalada pelo instalador do fornecedor. Nunca copiada para a fonte única.

Como

Como construir, em resumo

Resumo da regra oficial, docs/protocolos/CONVENCAO-AUTORIA-SKILLS.md. Na dúvida, vale o que está lá.

  1. Procure antes.Use o filtro da lista abaixo. Se existe uma parecida, melhore a existente.
  2. Escreva primeiro os cenários.Três pedidos reais em que o agente erra sem a skill. Eles são a linha de base.
  3. Nome e descrição.Nome aidd-<assunto> em inglês, igual à pasta, sem -runner e sem número. Descrição em inglês dizendo o que faz e "Use when…", com as palavras que você digita em português.
  4. Corpo curto.Inglês compacto, meta de 150 linhas, trava em 450. Material de consulta vai para references/; cada passo termina numa condição que dá para conferir.
  5. Distribua e confira.python ecossistema.py components sync --tipo skill, depois components verify, G_SKILL_ROT e G_SKILL_FORMATO, todos com exit 0.
  6. Teste de verdade.Rode os três cenários numa sessão nova. Se a skill não disparou sozinha, o problema está na descrição.
Pronto quando · quem confere

Como saber que a skill está pronta

Quem confere

  • G_SKILL_FORMATO: nome, "Use when", tamanho, prefixo aidd-
  • G_SKILL_ROT: todo caminho e comando citado existe; nenhuma cópia órfã
  • G_IDIOMA_LEI_4: corpo em inglês compacto
  • components verify: cópia idêntica em todos os harnesses

O que não fazer

Descrição sem "quando usar"

Era o motivo principal de skill que não disparava: em 26/09/2026, só 10 de 75 diziam quando usar.

A mesma skill com dois nomes

{{MESMA_DESCRICAO}}

Terceiros copiados para dentro

Skill de fornecedor copiada para a fonte única existe em dobro e envelhece. O components sync também não pode puxá-la de volta dos harnesses.

Renomear sem limpar as cópias

O components sync nunca apaga. A pasta antiga precisa sair de todos os harnesses, senão o G_SKILL_ROT acusa skill órfã.
