O quê · por quê · para quê

Por que o ecossistema precisa de guardas

O que é

Um script em Python, 100% máquina, sem LLM. Lê a saída de uma peça, confere bit a bit e devolve exit 0 ou exit 1, com uma mensagem dizendo o que achou e onde.

Por que construir

Uma regra escrita no AGENTS.md é só um pedido: o cérebro pode esquecer. O guarda transforma o pedido em trava. Regra sem guarda é conselho.

Para que serve

Para um erro conhecido nunca mais voltar. Cada vez que o mesmo erro mecânico aparece duas vezes, ele vira um guarda, e a partir daí o commit é barrado sozinho.

Quando

Quando construir, e quando não

Construa um guarda quando…

  • uma lei nova entra no AGENTS.md: toda lei precisa declarar o guarda que a prova;
  • o mesmo erro mecânico aconteceu duas vezes;
  • uma peça entrega algo que a próxima precisa receber num formato exato (um contrato);
  • uma ferramenta nova nasce: ela precisa de um guarda para o que produz.

Não construa quando…

  • já existe um guarda que confere a mesma coisa (procure na lista abaixo antes);
  • a conferência depende de julgamento ("o texto está bom?"): isso é revisão, não guarda;
  • não dá para escrever um teste que faça o guarda reprovar: sem isso, ele é de fachada;
  • a ideia é "copiar o guarda da outra ferramenta": chame o original em vez de copiar.
Onde

As quatro casas de um guarda

Onde o arquivo mora diz o que ele vigia e quem o chama.

Ecossistema

gates/G_*.py

Vigia este repositório. Roda em todo commit, pelo pre-commit. Precisa de teste em gates/test_g_<nome>.py.

Ferramenta

tools/<f>/gates/ ou tools/<f>/scripts/gates/

Vigia o que uma ferramenta produz. Roda dentro do fluxo daquela ferramenta.

Entrega

tools/<f>/templates/gates/

Vai junto com o app gerado e vigia o projeto do cliente. É uma cópia gerada por scripts/gerador_templates_gates.py: nunca edite à mão.

Meta

G_PORTAO_PROVA_QUE_MORDE, G_LEI_DECLARA_PORTAO

Guardas que vigiam os outros guardas: todo guarda tem prova de que reprova? Toda lei declara seu guarda?

Como

Como construir, passo a passo

Resumo da docs/protocolos/CONVENCAO-AUTORIA-GATES.md, que é a regra oficial. O exemplo é um guarda de ecossistema.

  1. Procure antes.Use o filtro da lista abaixo. Se já existe um guarda que confere a mesma coisa, melhore esse em vez de criar outro.
  2. Escreva primeiro o teste que quebra a regra.Em gates/test_g_<nome>.py, monte uma situação errada numa pasta temporária, rode o guarda e exija returncode == 1 e a mensagem de erro. O teste precisa falhar agora, porque o guarda ainda não existe. 
    def test_g_exemplo_reprova_quando_falta_readme(tmp_path):
    proc = rodar_gate("G_EXEMPLO.py", cwd=tmp_path)
    assert proc.returncode == 1
    assert "README.md ausente" in proc.stdout
  3. Escreva o guarda.gates/G_<NOME>.py: um docstring que diz o que confere e o que significam o 0 e o 1, só código mecânico (AST, regex, JSON Schema) e mensagem com arquivo, linha e como corrigir. 
    """G_EXEMPLO — confere que todo pacote em tools/ tem README.md.
exit 0 = todos têm. exit 1 = algum não tem (lista impressa)."""
import sys
from pathlib import Path

def main() -> int:
    faltando = [p for p in Path("tools").iterdir()
                if p.is_dir() and not (p / "README.md").is_file()]
    for p in faltando:
        print(f"[FALHA] {p}/README.md ausente: crie o arquivo.")
    return 1 if faltando else 0

if __name__ == "__main__":
    sys.exit(main())
  4. Teste também o caminho certo.No mesmo arquivo de teste, uma situação correta precisa dar returncode == 0.
  5. Ligue no commit.Acrescente um bloco no .pre-commit-config.yaml com entry: python gates/G_<NOME>.py.
  6. Declare na lei.Embaixo da lei que o guarda prova, no AGENTS.md, escreva - Portão: gates/G_<NOME>.py (provado). Deixe essa linha sem comentário depois do parêntese: hoje o meta-guarda não lê linhas com comentário (veja os erros comuns).
  7. Rode pelo mecanismo real.pre-commit run --hook-stage manual <id> --all-files, e pegue o código de saída na mesma linha, nunca depois de um | tail.
  8. Mensagem honesta.Diga exatamente o que foi conferido. Nada de "zero risco" ou "100% seguro" se a checagem é uma busca de texto.
Pronto quando · quem confere

Como saber que o guarda está pronto

Checklist

  • existe um teste que quebra a regra e exige exit 1
  • existe um teste do caminho certo com exit 0
  • o guarda não chama LLM e responde só 0 ou 1
  • a mensagem diz o que corrigir e onde
  • está no pre-commit (se for de ecossistema)
  • a lei que ele prova o declara no AGENTS.md
  • não existe outro guarda com o mesmo trabalho

Quem confere o guarda

  • G_PORTAO_PROVA_QUE_MORDE: exige o teste com exit 1 (Lei #13)
  • G_LEI_DECLARA_PORTAO: exige que cada lei declare seu guarda
  • G_SAIDA_BINARIA: exige saída só 0 ou 1 (Lei #2)
  • G_HONESTIDADE_ROTULO: barra promessa maior que a checagem (Lei #8)
  • G_DETERMINISMO_LEI_1: barra chamada de LLM em peça mecânica (Lei #1)
Erros comuns · encontrados neste ecossistema

O que não fazer

Guarda de fachada

A etapa 7 da Tríade grava "100% conforme" sem rodar nenhum guarda. Parece guarda, mas nunca diz 1.

Guarda que abre quando quebra

A validação de contrato do orquestrador responde "aprovado" quando falta o schema. O certo é reprovar quando não consegue conferir.

Mesma regra, várias versões

Guardas com o mesmo nome e código diferente em cada ferramenta. A lista abaixo marca cada caso com o selo versões.

G_BLOQUEAR_SEGREDOSG_CONTRACTSG_CYBERSECURITY_OWASPG_DETERMINISMO_LEI_1G_HARNESS_COMPATG_INJECTG_PERFORMANCEG_QUARTETO_SINE_QUA_NONG_SAIDA_BINARIAG_SEGREDOSG_TESTES_REAIS

Mesmo trabalho, nomes diferentes

G_ARQUITETURA (enterprise/master) e G_AST_BOUNDED_CONTEXT (master) barram a mesma coisa: import direto entre módulos. O selo "versões" não pega esse caso, porque os nomes são diferentes. Só procurar antes evita.
