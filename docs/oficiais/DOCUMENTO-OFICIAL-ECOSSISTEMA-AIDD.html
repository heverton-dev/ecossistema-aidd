1. Leis Invioláveis do Ecossistema

01

Determinismo Primeiro

Toda checagem estrutural, linting, AST e segurança é operada por scripts Python, Hadolint e Pytest. A IA nunca audita a si mesma com texto livre.

02

Qualidade Binária

Toda verificação mecânica produz apenas exit 0 (pass) ou exit 1 (bloqueio). Sem tolerância a avisos em produção.

05

Zero Stubs / Zero Mocks

100% de contratos tipados, banco de dados real em concorrência e testes reais. Proibido o uso de pass, TODO ou retornos fictícios em produção.

10

Criação de Aplicações

3. A Tríade Canônica de Criação

3 fluxos determinísticos especializados derivados da mesma fundação

Pipeline: [FORGE -> PLANNER] -> GENERATOR -> [MASTER -> ENTERPRISE -> OPS] Engine: aidd-generator

Construção de software autônomo do zero absoluto através de um pipeline de 8 fases sequenciais. Aplica rigorosamente o ciclo TDD Red-Green-Refactor: os testes unitários e de integração são gerados e forçados a falhar antes de qualquer linha de lógica de domínio ser implementada.

COMANDO CLI (Dev Sênior)

python ecossistema.py run-fluxo --fluxo pure --nome "Meu App" --slug meu-app --dominio saas

SLASH COMMAND (Leigo / Chat)

/pure "Construir sistema de cobrança recorrente com split de pagamentos"

Pipeline: [FORGE -> PLANNER] -> FACTORY -> [MASTER -> ENTERPRISE -> OPS] Engine: aidd-factory

Ideal para aplicações onde já existem motores Open-Source consolidados (ERPs, CRMs, N8N, Evolution API, Directus, etc.). Em vez de reinventar a roda, o ecossistema isola as engines em contêineres OCI herméticos e gera automaticamente o Gateway/BFF em FastAPI e o Frontend Next.js para unificação total.

COMANDO CLI (Dev Sênior)

python ecossistema.py run-fluxo --fluxo open --nome "Clínica" --slug clinica --dominio saude

SLASH COMMAND (Leigo / Chat)

/open "Portal de atendimento ao cliente multicanal com WhatsApp e N8N"

Pipeline: [FORGE -> PLANNER] -> BRIDGE -> [MASTER -> ENTERPRISE -> OPS] Engine: aidd-bridge

Desacoplamento e libertação de projetos construídos em plataformas Low-Code (Lovable, v0, Bolt). Elimina 100% das dependências de BaaS proprietários (Supabase Cloud, Clerk pago), compila schemas SQL para PostgreSQL puro com PostgREST e preserva a interface de usuário criada.

COMANDO CLI (Dev Sênior)

python ecossistema.py run-fluxo --fluxo bridge --origem ./exports/lovable --nome "Meu SaaS"

SLASH COMMAND (Leigo / Chat)

/bridge ./pasta-do-lovable meu-saas-proprio

Padronização Arquitetural

4. O Funil Universal de Convergência

Por que toda aplicação converge obrigatoriamente para Master, Enterprise e Ops

Etapa 1: AIDD Master

Harmonização VSA

Reorganiza o backend em Fatias Verticais (VSA) independentes. Gera a interface em Next.js 14 App Router (TypeScript + Tailwind) e injeta as 4 rotas dinâmicas do Quarteto Sine Qua Non.

Etapa 2: AIDD Enterprise

Selo SHA-256

Aplica injeção auditada de componentes de missão crítica: RBAC com Argon2id, Transactional Outbox, Rate Limiting distribuído e proteção OWASP. Sela o manifesto com hashes SHA-256 anti-adulteração.

Etapa 3: AIDD Ops

Deploy VPS

Executa o sizing do servidor, conecta via SSH/Ansible, sobe a aplicação em contêineres Docker sob proxy reverso Traefik com SSL automático Let's Encrypt e monitoramento ativo no Uptime Kuma.

Garantia Formal

5. Contratos Formais de Handoff (JSON Schema)

Transições entre ferramentas validadas por schemas matemáticos estritos

Planner ➔ Engine handoff-planner-to-engine.schema.json

Valida metadados, domínio, cenários BDD obrigatórios (Given/When/Then), dicionário formal de entidades com tipos e declaração do Quarteto Sine Qua Non.

Engine ➔ Master handoff-engine-to-master.schema.json

Exige código de produção, schemas Pydantic, rotas REST, DDL SQL de banco e evidência de testes unitários reais verdes (testes_passando = true).

Master ➔ Enterprise handoff-master-to-enterprise.schema.json

Verifica a estrutura VSA em features/, paridade OpenAPI 3.1, interfaces Next.js geradas e rotas operacionais ativas do Quarteto.

Enterprise ➔ Ops handoff-enterprise-to-ops.schema.json

Audita manifesto com hashes SHA-256, lockfiles auditados, credenciais blindadas e especificações de hardware/rede para provisionamento VPS.
