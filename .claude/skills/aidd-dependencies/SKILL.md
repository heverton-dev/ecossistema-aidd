# aidd-dependencies

Out of scope: an MCP that becomes part of a product or tool generated by the ecosystem (e.g. the `cloudflare-mcp` that `aidd-ops` exposes) follows `componentes/<scope>/mcps/<name>/server.py` and `aidd-mcp`.

## CLI

```bash
python ecossistema.py dependencia bootstrap [--tipo skills|mcps|todos] [--dry-run]
python ecossistema.py dependencia add-skill --nome <n> --pacote <p> --instalar "<command>" --verificar <path> [--gitignore "pattern1,pattern2"] [--sha256 <hash>]
python ecossistema.py dependencia add-mcp --nome <n> --pacote <p> --comando <cmd> [--args="a,b"] [--env VAR1,VAR2] [--harnesses claude-code,opencode,cursor,gemini-cli,mimocode,antigravity]
python ecossistema.py dependencia add-mcp --nome <n> --pacote <p> --tipo remote --url <url> [--harnesses claude-code,opencode,cursor,gemini-cli,mimocode,antigravity]
python ecossistema.py dependencia list
python ecossistema.py dependencia verify
```

If the first `--args` value starts with `-` (e.g. `-y,package@latest`), always write `--args="-y,package@latest"` with `=`; otherwise argparse reads it as a new flag.

## Protocol

1. **`bootstrap`:** no questions. Run `python ecossistema.py dependencia bootstrap` and report the result. It is the "first use after clone" command.
2. **`skill <request>`:** agree with the user on short name (kebab-case, the vendor's original name), exact package, full install command (prefer the vendor's official installer, e.g. `npx -y skills add <owner>/<repo> --skill <name> ...`) and a file that exists only after install (`--verificar`, used for idempotence). If the user does not know the command, ask for the package link and propose one for confirmation before running. Then run `add-skill`. Pass `--gitignore "*/skills/<name>/"` so the installer footprint is never committed. Never copy a third-party skill into `componentes/`.
3. **`mcp <request>`:**
   - **stdio** (local process): short name, real package/command (e.g. `npx -y @playwright/mcp@latest`) and the **names** of required environment variables (never ask for or write a secret value, only the variable name, e.g. `GITHUB_TOKEN`). Remind the user to export the real value on their machine.
   - **remote** (HTTP endpoint, e.g. `https://mcp.cloudflare.com/mcp`): short name and URL, with `--tipo remote --url <url>`.
   - Harnesses with a confirmed MCP schema: `claude-code` (`.mcp.json`), `opencode` (`opencode.jsonc`), `cursor` (`.cursor/mcp.json`), `gemini-cli` (`.gemini/settings.json`), `mimocode` (`mimocode.jsonc`, its own file) and `antigravity` (`.agents/mcp_config.json`). Prefer all six unless the user restricts. Any other harness needs its official schema confirmed before extending `DESTINOS_MCP`.
4. **Always finish** with `python ecossistema.py dependencia list` and report the real status. Done when the listed status confirms the install or registration.

## Registered file is not an available variable

`${VAR}` in `.mcp.json`, `opencode.jsonc` etc. only works if `VAR` is already in the environment of the shell that launches the harness. No harness loads the repository `.env` to expand third-party MCP variables. The root `.env` (see `.env.example`) documents the names and is loaded by this repository's Python code, but the user still exports them before opening the harness.
