## Matriz de Decisoes Tecnicas

| Decisao | Escolha | Justificativa |
|---------|---------|---------------|
| Engine de templates | Jinja2 | Mesmo usado por aidd-generator, padrao do ecossistema |
| CLI framework | Click | Consistente com aidd-ops e ecossistema.py |
| Result monad | copies compartilhado | Byte-identica, sincronizada via gestor_componentes |
| Gateway framework | FastAPI | 30-80MB RAM, nativo Python, OpenAPI automático |
| Frontend framework | Next.js | SSR/SSG, BFF integrado, shadcn/ui nativo |
| Validacao JSON | jsonschema (Draft 2020-12) | Padrao do ecossistema, ja usado em aidd-ops |
| Secret generation | OpenSSL rand | Deterministico, auditavel, sem dependencia LLM |
| Gates | AST + py_compile | Padrao comprovado em G_OPS_MVP e G_OPS_SSH |

---

## Riscos e Mitigacoes

| Risco | Probabilidade | Mitigacao |
|-------|---------------|-----------|
| LLM gera codigo inseguro no gateway | Media | Gate AST + bandit scan + testes E2E |
| Compose gerado tem conflito de portas | Baixa | compose_preflight.py + G_FACTORY_COMPOSE |
| Frontend whitelabel nao compila | Media | Template testado + CI gate |
| Webhook contracts inconsistentes | Media | JSON Schema validation + cross-service test |
| Custo tokens LLM alto | Baixa | Budget por fase + fallback deterministo |

## Ordem de Dependencias

```
FASE 0 (fundacao)
  └─> FASE 1 (analisador)
        └─> FASE 2 (gateway + frontend) [paralelizavel com FASE 3]
        └─> FASE 3 (docker + initdb + env)
              └─> FASE 4 (webhooks + docs + integracao)
                    └─> FASE 5 (gates + testes)
                          └─> FASE 6 (integracao cross-tool)
```

FASEs 2 e 3 podem ser paralelizadas (gateway/frontend vs docker/initdb/env).
FASE 4 depende de ambas (usa artefatos de gateway + compose).
FASE 5 depende de FASE 4 (gates validam todos os artefatos).
FASE 6 e finalizacao.
