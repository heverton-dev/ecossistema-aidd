# aidd-plan (step 2 of 3)

Flow: `/melhoria` -> **`/plan`** -> `/orchestrate`. No step triggers the next one by itself (Golden Rule #7, `AGENTS.md`). Arriving without step 1 is valid: just confirm where the grade evidence comes from.

## Fixed rules

1. Never decide or approve alone: everything is delivered as **DRAFT**, "awaiting approval". No scope, architecture or item approval may be fabricated.
2. Determinism first: structure and fence checks come from `python ecossistema.py plan ...`, never hand-written.
3. Never send prompts to executor agents alone.
4. No git commit or push.
5. Explicit scope: every plan carries "Ainda nao especificado" and "Fora de escopo". An out-of-scope item never returns to the current plan; if it matters again it becomes a new initiative.
6. Tests run in an isolated temporary directory, never in `docs/planos/`.
7. Folder names are `PLAN-<NNNN>-<3-word-name>`, generated by `plan init`. Never build them by hand. Details: `references/plan-structure.md`.

## Protocol

1. **Start only on an explicit request.**
2. **Scope gate with the user** before writing anything: initiative name, goal, preliminary item list, and **current grade, target grade (0-10) and real evidence** for the initiative and for each item. Evidence is an existing report (e.g. from `/melhoria`), a command or a test run now. Without evidence the grade is `NAO AUDITADO`. Done when the user confirmed all of it.
3. **Generate deterministically:**
   ```bash
   python ecossistema.py plan init <initiative-name> --itens "Item 1" "Item 2" \
     --notas-atuais "6" "5" --notas-alvo "9" "8" --evidencias "docs/melhorias/<report>.html" "" \
     --nota-atual-geral "6" --nota-alvo-geral "9" --evidencia-geral "docs/melhorias/<report>.html"
   ```
   Grade flags are optional and positional (same order as `--itens`). An empty evidence forces `NAO AUDITADO` for that item. Done when the command exits 0.
4. **Check markdown fences:**
   ```bash
   python ecossistema.py plan check-fences docs/planos/<initiative-name>/
   ```
   Done when it exits 0.
5. **Strict stop:** show the created paths and hand control back. Never mark items approved or done without the user's verdict.
6. **Only after explicit approval** ("aprovado", "pode seguir com esse plano"), never by inference:
   ```bash
   python ecossistema.py plan aprovar <plan-folder>
   ```
   It turns every item from DRAFT to APPROVED and moves the folder to `docs/planos/a-fazer/` through `scripts/atualizar_index_planos.py`. Never move a plan folder by hand.
7. Then ask whether to start `/orchestrate`. Never start it alone: it has its own environment gate.

## Do not use when

- Measuring the code before a plan exists -> `/melhoria`.
- Executing an approved plan -> `/orchestrate`.
- Editing the technical content of an item -> edit its `NN-<item>.md` directly.

## CLI

```bash
python ecossistema.py plan init <name> --itens "Item 1" "Item 2"
python ecossistema.py plan check-fences <path-or-folder>
python ecossistema.py plan aprovar <plan-folder>
python ecossistema.py plan iniciar-execucao <plan-folder>
python ecossistema.py plan ler-nota <path> [--item <NN>]
python ecossistema.py plan atualizar-nota <path> [--item <NN>] --nota-atual <n> --evidencia <path>
```

## Negative Guardrails

- NEVER run `python ecossistema.py plan aprovar` without a literal approval message from the user in this session; an "APROVADO" on the plan approves the document only, so never chain `plan iniciar-execucao` or `/orchestrate` from it.
- NEVER write a grade without evidence: `plan atualizar-nota` exits 1 without `--nota-atual` and `--evidencia`; never pass a fake path to get past it, use `NAO AUDITADO`.
- NEVER create, rename or move folders under `docs/planos/` by hand; numbering comes from `plan init` and the move to `docs/planos/a-fazer/` from `plan aprovar`.
- NEVER file a tool-audit correction plan here: that is `PLANO-EVOLUCAO.md` under `docs/auditoria/<tool>/` (`aidd-audit-4f`), not `docs/planos/`.
- NEVER run `git commit`, `git push` or `--no-verify` from this skill, and never point the `test_gerenciador_planos.py` fixtures at the real `docs/planos/`.

## Failure Modes & Fallback

- **`[ERRO] Pasta ja existe` (exit 1) on `plan init`:** never delete the existing folder; read it with `python ecossistema.py plan ler-nota <plan-folder>` and ask the user: reuse it or pick a new initiative name.
- **`check-fences` exit 1:** a code fence is nested inside another; switch the outer fence of the reported file to `~~~` and rerun until exit 0.
- **`aprovar` says the folder does not exist:** look in `docs/planos/a-fazer/` and `docs/planos/fazendo/`; the plan may be approved already (re-approval is idempotent). Report it, never recreate it.
- **Another session edits the same plan:** run `git status docs/planos/` before writing; if a file changed under you, stop and ask the user which session owns it.

## Stopping Checklist

Exit codes go to a file, never through a pipe: `<cmd> > "$TEMP/plan.log" 2>&1; echo $? > "$TEMP/plan.rc"`.

- [ ] `python ecossistema.py plan check-fences docs/planos/<plan-folder>/` wrote rc 0.
- [ ] `python ecossistema.py plan ler-nota docs/planos/<plan-folder>` shows, for every item, a current grade with evidence or `NAO AUDITADO`.
- [ ] Every item file still reads DRAFT unless the user approved in this session.
- [ ] `python -m pytest componentes/compartilhado/skills/aidd-plan/tests/test_gerenciador_planos.py -q` wrote rc 0 when this skill or `scripts/gerenciador_planos.py` changed.
- [ ] No `git commit` or `git push` ran.
